# Community input-to-output workflow

This is the workflow for **this public GitHub project** only. GitHub is a source collaboration platform, not an authority over any private runtime or financial service.

1. **Observe a public problem.** Open a Discussion identifying a particular blockchain protocol ambiguity, accessibility defect, data provenance issue, or reproducible need.
2. **Scope the task.** Link a public specification and describe expected behavior, chain/network and invalid cases. Open an Issue only after a bounded deliverable is clear.
3. **Contribute independent public material.** Use a fork or branch, explicit file allowlist, synthetic examples and clearly licensed sources; never mirror a confidential repository or Git history.
4. **Run tests.** Verify the public Python suite and relevant new deterministic fixtures; inspect staged files, history, external dependencies and generated artifacts.
5. **Review for publication.** Check correctness, source/license provenance, confidential material, personal data and security. A successful CI run is necessary for merges but **not** sufficient for intellectual-property clearance.
6. **Merge and explain.** Merge through the protected PR workflow with actual passing checks, document limitations and link the relevant public issue.
7. **Iterate.** Community review can uncover new regressions, better specifications and missing test vectors; follow with another bounded public issue.

## Four review dispositions

- `PUBLIC_PROTOCOL`: independently cited public standards and educational explanations
- `PUBLIC_ORIGINAL`: original code/documents created for this public project
- `PUBLIC_SYNTHETIC`: fabricated test fixtures with no personal account data
- `HOLD`: uncertain rights, private implementations, novel unpublished inventions, credentials or protected design details

The public source license applies only to this repo. No private system, wallet, hosted explorer, runtime, credentials or user information is part of this workflow.

### How to help without writing code

A specific confusion with a citation, a synthetic failing example, a reproducible visual defect, a test idea or an accessibility problem is a valid starting contribution. Begin in [Discussions](https://github.com/Footloose9/hyperfabric-evolution/discussions).

Progress can be evaluated by merged reproducible fixes, contributor onboarding success, standards-backed tests, unresolved issue age and security/publication review quality—not by raw issue counts alone.
